Scope and caveats

The picture starts below the neuron. The chapter's forward pass runs w, x and b through a sigmoid to reach a; that single chain is the one-chain excerpt, which names branch accumulation as the thing it leaves out. This panel picks the derivative up at a and puts the trunk back in only at the end, as one grey factor, so that the arithmetic lands on the gradient the chapter prints.

The two subtraction nodes are drawn apart because the chapter's line evaluates (a + (-0.3)) twice and the engine therefore builds two nodes, each recording a as a parent. Written once and multiplied by itself, it would be a single node with the same parent recorded twice, and the accumulation would be identical: the product rule adds one contribution per recorded use, not one per line of source.

The hollow bar under the meter is a counterfactual, not a second model: it marks where the counter would stop if the rules assigned with = instead of accumulating with +=, and the struck number beside it is what the chapter would then have printed. Every value shown is recomputed from the declared inputs with the chapter's own value of e, at four decimal places; the loss value itself is never drawn, because only its seed of one enters the backward pass. Green is the activation the chapter computes, purple the target it is compared against, wine the blame travelling back, orange the learnable weight, grey the scenery and the trunk.

Check yourself. Change one digit so the second subtraction takes 0.1 away instead of 0.3 — the same activation, two different targets. What does the counter on a read now, and is it still twice one branch?

1.0219, and no. The product rule sends each branch the other branch's value, so the upper edge carries 0.6109 and the lower carries 0.4109, and the counter holds their sum. Doubling was never the rule; it was what equal branches happened to give. The trunk then prints 0.4200 instead of 0.3378.
