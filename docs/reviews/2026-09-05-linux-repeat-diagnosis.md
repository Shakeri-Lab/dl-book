## Corrections and discriminating probe

Suppress the uninformative returned Generator display without changing its seed
call. Give every authored native cell a stable label, including currently silent
cells. Keep public figure labels unchanged. A real-Quarto pretraining witness
must compare complete generated bytes across two independent tiny projects, not
only their printed values.

Do not round or normalize frozen figure files to make them pass. First test the
two small least-squares inputs behind the changed figures in the exact saved
image, without training. The diagnostic source and the older image source have
separate identities. Preserve the original image verifier, archive checksum,
loaded image ID, CPU/flags, library configuration, and actual environment.

The ranked hypotheses and their predictions are:

1. Repeated least-squares calls vary despite identical input bytes. Repeated
   solves inside one process will expose this; alternative drivers are separate
   controlled comparisons, not presumed fixes.
2. A fresh process or numerical dispatch path changes the result. Fresh-process
   repeats with otherwise fixed inputs/policy will differ, while a within-process
   repeat can remain stable. Record tensor layout/alignment rather than assuming
   it is immaterial.
3. Plot export varies despite fixed coordinates. A plot-only control with exact
   coordinates, authored labels, and a fixed source epoch will expose this.

The proposed dispatch variants are diagnostics only. A finite successful probe
does not guarantee universal host independence. Any source or runtime correction
still needs two new complete same-source, exact-image executions with the original
all-file requirement before promotion.

The `98349c8` candidate and both accompanying Mac profiles were cancelled when
this full-file discrepancy was discovered. Their partial records stay rejected;
there is no second `98349c8` independent run to dispatch. Finish the minimal
diagnosis and corrections before starting another full execution cycle.

The candidate source correction names `driver="gelsd"` at all seven CPU
least-squares calls in Chapters 1, 4, 18, and Appendix A1. This is an explicit
SVD-based, rank-aware numerical-method choice, not a tensor-rounding patch or a
runtime monkeypatch. In particular, Chapter 18 intentionally uses a singular
incidence matrix; replacing everything with full-rank-only `gels` would break
its contract. The API/device boundary follows the
[pinned-version PyTorch documentation](https://docs.pytorch.org/docs/2.12/generated/torch.linalg.lstsq.html).
Inputs, seeds, dtype, default `rcond`, dispatch policy, and all existing assertions
and tolerance gates remain unchanged. Appendix A1's prose now describes roundoff
scale rather than committing to one tiny residual's leading digits.

The actual authored seven-call prefixes must pass the new pretraining byte

same exact image must pass the original all-file gate. This finite diagnostic
supports that candidate repair; it is not itself a release or promotion proof.
